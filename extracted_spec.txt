1. Product Definition and Scope
CaterPrep is a mobile application for caterers/chefs who currently prepare ingredient requirement lists on paper. The application digitizes that workflow while keeping it simple, fast, bilingual and suitable for real catering work.
The caterer creates a client/event record, selects ingredients, enters quantities and units, reviews the final list, then shares it with the client. The client does not require an account and does not edit the list inside the app.

1.1 Product Objectives
Replace printed/handwritten catering ingredient lists.
Reduce rewriting when quantities or items change.
Store ingredient names in Kannada and English.
Provide fast quantity and unit entry.
Allow reusable templates and duplication of previous lists.
Create a professional client-facing preview/PDF.
Share the final list using WhatsApp or the device share sheet.
Keep the application usable even with limited connectivity.
1.2 Explicitly Out of Scope for the MVP
No Chef Checklist workflow.
No Pending / Purchased / Packed / Ready statuses.
No purchasing progress or reminders such as “8 items still need purchase”.
No chef/team management.
No client login.
No restaurant ordering, delivery or payment flow.
No inventory/warehouse management.
One-user model
There is only one application user type: Caterer/Chef. Authentication may still be used for cloud backup, but there is no role-based user system in the MVP.


2. User Model and Core Workflow
2.1 Primary User
Caterer / Chef — the person who creates and manages ingredient requirement lists for clients.
Create and edit client/event lists.
Select master ingredients or create custom ingredients.
Enter quantity and unit.
Reorder and remove items.
Preview the client-facing document.
Save, duplicate and reuse previous lists.
Create templates.
Generate PDF and share with the client.
2.2 Client
The client is a recipient, not an application user. Client data is stored only to identify and format the catering list. The client receives a PDF or shared document/message.
2.3 Core Workflow
Welcome  ↓Dashboard  ↓Create New List  ↓Client / Event Details  ↓Select Ingredients  ↓Enter Quantity + Unit  ↓Client Preview  ↓Validate List  ↓Save / PDF / WhatsApp / Share

12. Offline Storage and Synchronization
The application should remain useful when network connectivity is weak. Firestore offers offline persistence on mobile, while Hive can hold local settings, seeded catalogs and drafts where appropriate.
Save draft form state locally.
Cache ingredient catalog and categories.
Allow editing previously loaded lists offline.
Queue changes and sync when connectivity returns.
Show a subtle “Saved locally / Syncing” indicator when needed.
Keep sync simple
Because there is only one owner user, the MVP can use a simple latest-update-wins approach using updatedAt timestamps. Complex collaborative conflict resolution is unnecessary.

15. Security and Privacy
Use Firebase Authentication if cloud data is enabled.
Firestore security rules must restrict data to the authenticated owner.
Do not expose Firebase administrative credentials in the Flutter client.
Validate user input before database writes.
Store only necessary client information.
Business logo uploads should validate file type/size.
Do not permanently upload generated PDFs unless the feature requires cloud history.
If the MVP is initially local-only, Firebase Authentication can be deferred. Once cloud backup is introduced, authentication becomes recommended.
